# 安全边界与数据流向（Security Boundary）

> 对应 Roadmap `A34`。本文回答的是**事实问题**：「这个程序到底把什么数据发到哪里、我能关掉什么」。
> 政策层（怎么报漏洞、我们不接受哪类「安全」工作）见仓库根目录 `SECURITY.md`。
>
> 最后核对：2026-10-08，基线 v0.1.0 + `main`。

---

## 一、四条数据路径（唯一需要关心的四件事）

```text
  [A] QQ 群 ──NapCat/NTQQ──▶ OneBot 接收器(8765) ──▶ 本地 SQLite + 附件缓存
                                                        │
                                     白名单 + 规则打分 + 去重 + 截断（max_items）
                                                        │
                        ┌───────────────────────────────┴───────────────────────────┐
                        ▼                                                           ▼
        [B] 可选：阿里云 DashScope（只发筛选后的候选文本）        [C] 推送通道（只发最终摘要）
                        │                                                           │
                        └──────────────▶ 本地 SQLite ◀─────────────────────────────┘
                                                     ▲
                                        [D] 手机/浏览器 待办台(8766，token 鉴权)
```

### A. QQ → 本机（接收，只读）

| 项目 | 事实 |
| --- | --- |
| 数据 | 白名单群的**群消息 / 群文件 / 群图片事件** |
| 入口 | OneBot v11 HTTP 上报，默认 `127.0.0.1:8765`（`QQ_DIGEST_ONEBOT_HOST` 可改） |
| 鉴权 | `QQ_DIGEST_ONEBOT_TOKEN`；**未设置时只允许监听 `127.0.0.1` / `localhost` / `::1`**，监听非回环地址会直接拒绝启动，启动日志与 `doctor` 都会告警 |
| 落盘 | `data/qq_live_digest.sqlite3`（messages / processed / digests / deliveries / tasks）、`data/files/` 附件缓存 |
| 是否回写 QQ | **否**。代码不调用 QQ 发送接口 |

> 风险点只有一个：把接收端口暴露到局域网却没有设 token——这种配置现在会**直接拒绝启动**。
> **只监听 `127.0.0.1` 是没有鉴权的可接受前提。**

### B. 本机 → 阿里云 DashScope（可选 AI，唯一的外发聊天内容路径）

仅在 `QQ_DIGEST_LLM=1`（默认）**且**配置了 `DASHSCOPE_API_KEY` 时发生。发送前已经过：
群白名单 → 本地规则打分 → 跨群去重 → 按分值排序并截断到 `QQ_DIGEST_MAX_ITEMS`（默认 30，单次请求上限 50 条）。

| 项目 | 事实 |
| --- | --- |
| 发送内容 | **筛选后候选消息的文本**（群名、发送者昵称、正文） |
| 不发送 | 全量原始群消息、非白名单群、QQ 密码/登录态、好友列表、QQ 客户端本地数据 |
| 附件 | 开启 `QQ_DIGEST_ATTACHMENTS` / `QQ_DIGEST_VISION` 时，会把**附件文本或被识别图片**交给同一端点做 OCR/摘要 |
| 端点 | `QQ_DIGEST_LLM_ENDPOINT`，默认 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`，**可指向自建网关或本地兼容服务** |
| 传输 | HTTPS，凭据仅在 `Authorization: Bearer` 头 |
| 关闭方式 | `QQ_DIGEST_LLM=0`（或清空 `DASHSCOPE_API_KEY`）→ 完全本地规则，**零外发** |

> **这是本项目唯一「把群聊内容发给第三方」的地方。** 如果群里有人明确反对内容出本机，请关掉这一项。
> 关掉之后功能不残：本地规则仍会产出通知与待办，只是摘要不如模型精炼。

### C. 本机 → 推送通道（出站，只发结果）

- 通道：WxPusher / Server酱 / PushPlus / 自定义 Webhook / QQ 官方机器人私聊。
- 发送的是**最终摘要文本**（正文、待办、截止时间），不是原始聊天记录。
- 凭据（AppToken / SendKey / Webhook URL）保存在 `.env`，**不入库、不入库表、不写日志**。
- 推送失败按配置回退到下一个通道，并记录到 `deliveries` 表。

### D. 手机 / 浏览器 → 待办台（8766）

| 项目 | 事实 |
| --- | --- |
| 鉴权 | `QQ_DIGEST_WEB_TOKEN`；**未配置时首次启动自动生成** `secrets.token_urlsafe(12)` 并存入 SQLite `meta` 表的 `web_token` |
| 默认绑定 | `0.0.0.0`（`QQ_DIGEST_WEB_HOST` 可改）——比 OneBot 更容易被误暴露 |
| 能力 | 只读列表 + 有限写（把待办标记完成 / 忽略 / 纠错 / 稍后提醒），写操作只改本地 SQLite |
| 是否碰 QQ | **否** |

> 推荐：`QQ_DIGEST_WEB_HOST=127.0.0.1` + Tailscale（或反代加 TLS），而不是直接把 8766 暴露到公网。

### 明确不存在的行为

- **不回写 QQ**：没有「发送群消息 / 踢人 / 改群设置」的调用。
- **不采集账号凭据**：项目不做 QQ 登录，不读 QQ 客户端数据目录，不接触密码。
- **不外发未筛选内容**：只有路径 B 会外发内容，且只发筛选后的候选。

## 二、配置加固清单

装完之后照着过一遍；`python main.py doctor` 会逐项告诉你哪条没过。

| # | 动作 | 怎么确认 |
| :-: | --- | --- |
| 1 | 设置 OneBot 上报 token：`QQ_DIGEST_ONEBOT_TOKEN=<随机串>`（NapCat 侧同步配置） | `doctor` 中「OneBot 接收器」为 OK |
| 2 | 确认接收器不必对外：保持 `QQ_DIGEST_ONEBOT_HOST=127.0.0.1` | `netstat -ano \| findstr 8765` |
| 3 | 待办台设 token，或改 `QQ_DIGEST_WEB_HOST=127.0.0.1`，或放 Tailscale 后面 | `doctor` 中「待办台」「访问层」无 WARN/FAIL |
| 4 | 明确 AI 外发范围：接受就保留 `QQ_DIGEST_LLM=1`，不接受就设 `0` | `doctor` 中「大模型」一行的说明 |
| 5 | 备份 `.env`（含全部凭据），但**不要**提交到 Git | `git status` 中无 `.env` |
| 6 | 只在白名单群里工作：`QQ_DIGEST_GROUPS` 逐群列出 | `doctor` 中「群白名单」为 OK |
| 7 | 定期更新依赖（见第四节） | `pip list --outdated` |

## 三、第三方安全审计（2026-10-08）核实与处置

审计对象是 v0.1.0 的两个发布包（zip / tar.gz，43 个文件，逐文件 SHA-256 一致）。
结论是「暂未发现恶意程序证据，但存在配置不当导致隐私泄露的风险」。我们逐条核实如下：

| 审计条目 | 审计结论 | 我们的核实 | 处置 |
| --- | --- | --- | --- |
| Web 界面监听 `0.0.0.0` | 较高风险 | 属实；缓解措施确实存在：未配置 token 时自动生成 `secrets.token_urlsafe(12)` 存 `meta` 表 | 写入加固清单第 3 条；`doctor` 对「对外监听 + 无 token」直接判 FAIL |
| OneBot 接口未设 token 时无鉴权 | 较高风险 | 属实，且项目**自己就会报**：`config.problems()` 与 `doctor` 都会提示 | 已加固：未设 token 且监听非回环地址时 `OneBotReceiver.start()` 直接拒绝启动；加固清单第 1 条 |
| 开机自启 + 隐藏窗口 | 需要知情 | `install-task.ps1` 注册登录任务、`run-hidden.vbs` 隐藏窗口，属后台常驻服务的正常设计 | 保持；在 `docs/FAQ.md` 说明如何卸载 |
| 聊天内容发往外部 AI | 隐私风险 | 属实，是设计内的**可选**路径，且只发筛选后的候选（见路径 B） | 写入本文档；`CHANGELOG` 与 `FAQ` 明确「关掉即零外发」 |
| 依赖供应链安全 | **审计未完成** | 本次补齐，见第四节 | 已核查；发现「传递依赖未锁版本」的缺口，列为后续动作 |
| 133 项测试有 1 项报错 | 审计环境缺 `qq-botpy` | **已定位为真实缺陷**：`bot.py` 在 import 阶段 `raise SystemExit`，而 `service.py` 模块级导入它，导致「少装一个可选依赖 = 整个程序/测试套件退出」 | 已修复（见第五节）；现在缺 `qq-botpy` 时全套测试仍通过 |

> 审计提到的「GitHub 在线仓库未能独立核验」：本次已核验，线上 `main` 与本地工作树一致，
> 仓库为 MIT、公开，受控文件与发布包同源。

## 四、依赖供应链核查（2026-10-08）

方法：把 `requirements.txt` 的固定版本 + 运行时传递依赖送 [OSV.dev](https://osv.dev) 批量查询已知漏洞，
并对比 PyPI 最新版本。

| 包 | 项目锁定 | PyPI 最新 | 已知漏洞（OSV） |
| --- | --- | --- | --- |
| `qq-botpy` | 1.2.1 | 1.2.1 | 无 |
| `openpyxl` | ≥3.1,<4 | 3.1.5 | 无 |
| `pillow` | ≥10,<13 | 12.3.0 | 无 |
| `pypdf` | ≥5,<7 | 6.19.0 | 无 |
| `pypdfium2` | ≥5,<6 | 5.14.0 | 无 |
| `aiohttp`（经 qq-botpy 传递引入） | 未锁定 | 3.14.4 | 无 |
| `PyYAML`（经 qq-botpy 传递引入） | 未锁定 | 6.0.3 | 无 |

**结论**：本次核查的全部依赖在查询时点均**无已知漏洞公告**，直接依赖也都是当前最新版。

**已知缺口（诚实记录）**：

1. **传递依赖未锁版本**。`aiohttp`、`PyYAML` 等由 `qq-botpy` 间接拉取，`pip install -r requirements.txt`
   解析到哪个版本取决于安装时间——即「测试通过的版本」和「你装到的版本」可能不同。
2. `openpyxl`/`pillow`/`pypdf`/`pypdfium2` 使用范围约束而非精确锁定，同样存在漂移。
3. 「无已知漏洞」只说明**当时**没有公开公告，不等于不存在未公开问题。

**后续动作**（已进入 Roadmap 候选池）：引入 `requirements.lock`（`pip-compile` 生成，带哈希），
并在 CI 中增加 `pip-audit` 步骤，让供应链检查变成每次提交的自动动作，而不是一次性人工核查。

## 五、本项目的安全取舍

### 可选依赖必须能降级

`qq-botpy` 是**可选依赖**：缺它时只应失去「QQ 官方机器人」这一个通道，其余能力照常。
2026-10-08 前的实现违反了这个约定（import 阶段 `SystemExit`），现已修复并有回归测试锁定
（`tests/test_optional_deps.py`：在没有 `qq-botpy` 的环境里，全套测试仍须通过）。

### 我们不提供的保证

- 不提供「永不被风控」的保证，也不做任何规避平台风控的实现。
- 不让 AI / Agent 自主操作 QQ（发送、踢人、改群设置）。
- 不保证第三方组件（NapCat / NTQQ）的安全性与可用性——它们本身即带账号风险，请自行评估。
- 不做「单机数据加密存储」的承诺：SQLite 与附件缓存是**明文**的，请依赖操作系统账户权限与磁盘加密。

### 报告问题

见仓库根目录 `SECURITY.md`。请勿在公开 Issue 中披露未修复的漏洞。
