# 评测集与基线数字（Roadmap A21）

这份文档回答一个问题：**改了规则、换了模型、动了阈值之后，系统是变好了还是变坏了？**
答不了这个问题，"调优"就只能靠感觉——所以这里有一份**脱敏、可复现**的评测集，
以及一组每次都能跑出同样结果的指标。

## 怎么跑

```powershell
.\.venv\Scripts\python.exe main.py benchmark                      # 500 条 / seed=20261008
.\.venv\Scripts\python.exe main.py benchmark --count 2000 --seed 1
.\.venv\Scripts\python.exe main.py benchmark --json               # 全部指标，含每类消息的明细
.\.venv\Scripts\python.exe main.py benchmark --fail-under 0.9     # 召回低于 90% 时退出码 1（给 CI 用）
```

代码里也可以直接用：

```python
from qq_live_digest import benchmark

report = benchmark.run(count=500, seed=20261008)   # 默认临时目录，跑完即弃
print("\n".join(report.summary_lines()))
print(report.as_dict())                            # 可 JSON 序列化的全部指标
```

三条承诺和 `simulate` 一样：**不联网**（内存假通道 / 关大模型 / 自动回退本地规则）、
**不碰 `data/`**（临时目录）、**确定性**（同 `seed` 必得同一组数字）。
`tests/test_benchmark.py` 把它锁进了 CI：召回 / 误报 / 待办 / 截止时间都有下限，掉下去就红。

## 评测集从哪来：意图标注

评测集不另外造，直接用 A20 模拟器的数据。`simulator.generate()` 给每条消息附一个
`_expect` 块，写明这条消息**期望**的结局；它会随 JSONL fixture 一起往返，所以离线也能评测：

| 字段 | 含义 |
| --- | --- |
| `kind` | 剧本类型（通知 / 作业 / 考试 / 紧急 / 后勤 / 报名 / 选课链接 / 闲聊 / 广告 / 跨群转发…） |
| `push` | `true` 该推、`false` 明确是噪声、`null` 不计入（附件、跨群转发副本这类边界样本） |
| `todo` | 该不该进待办库 |
| `deadline` | 文本里有没有承诺一个截止时间（由剧本里的 `{when}` 自动推出） |

`null` 是刻意的：图片、文件、跨群转发副本既不判为"该推"也不判为"噪声"，
免得把边界样本硬算成漏召或误报。

## 指标怎么算

| 指标 | 定义 | 为什么这么算 |
| --- | --- | --- |
| **召回** | 标 `push=true` 的消息里，被系统**认出来**的比例（推送 / 被去重 / 超上限 都算认出） | 去重与窗口合并是正常行为，不该算漏召 |
| **送达率** | 同上，但只算**真推出去**的比例 | 与召回分开看，差额就是被同批条数上限或去重挡下的量 |
| **误报** | 标 `push=false` 的噪声（闲聊 / 课程闲聊 / 广告）里被推出去的比例 | 误报的代价是打扰用户 |
| **待办判定** | 该进待办、且真进了摘要的候选里，落进待办库的比例 | 分母只算进了摘要的，被去重的不该拉低命中率 |
| **截止时间** | 标了 `deadline`、且真进了摘要的候选里，解析出结构化截止时间的比例 | 同上 |
| **跨群去重** | 同一内容在同一窗口里第二次出现（第一次是可推正类）时，被判 `deduped` 的比例 | 不依赖标注，直接看行为 |
| **延迟** | 消息到达 → 它所在那次推送的窗口结束（分钟），报中位数与 P95 | 批量摘要的核心体验指标 |
| **成本** | 本轮全部模型调用的次数 / token / 折合费用（`A5` 的 `llm_calls`） | 离线回放走本地规则，通常为 0；线上才有参考价值 |
| **置信度** | 三档（高 / 中 / 低）各多少条 | `A7` 的解释性指标 |

## 第一版基线（v0.3.0 前）

500 条消息 / `--seed 20261008` / 窗口 30 分钟 / 不限额度（评测默认 `--budget 0`）：

| 指标 | 基线 | 备注 |
| --- | --- | --- |
| 召回 | **86/86 = 100.0%** | 该推的一个没漏（含被去重、被上限挡下的） |
| 送达 | 60/86 = 69.8% | 差额 26 条是同一批超出条数上限 / 被去重 |
| 误报 | **2/380 = 0.5%** | 380 条噪声里 2 条被推（1 条闲聊、1 条课程闲聊） |
| 待办 | **60/60 = 100.0%** | 待办库共 64 项（见下面「已知噪声」） |
| 截止时间 | **60/60 = 100.0%** | `今天 18:00` / `本周五 23:59` 这类都解析出来了 |
| 跨群去重 | **4/4 = 100.0%** | 同一条通知被两个群转发，只留一条 |
| 延迟 | 中位 **0.0** 分钟 / P95 **31.6** 分钟（69 条要点） | 见下面「延迟怎么读」 |
| 成本 | 0 次调用 / 0 token | 离线回放用本地规则；线上按 `llm_calls` 统计 |
| 置信度 | 高 62 / 中 5 / 低 2 | 低置信度会进人工确认（A8） |
| 漏斗 | 500 条 → 过滤 377 / 去重 54 / 推送 69 条要点 | 与 `main.py simulate` 一致 |

## 怎么读这些数字

- **延迟中位数 0.0 分钟**：一半以上的要点是"到达即推"的（紧急通知即时出、突发批次很快
  攒满上限），在一次调度里就出去了；P95 31.6 分钟代表另一半老老实实等满 30 分钟合并窗口。
  回放的调度时钟走固定步长，批量 tick 的时间戳可能比它刚吃进去的消息早不到一步，
  这类按 0 记，不出现负延迟。
- **成本为 0**：离线回放关掉了大模型，全部走本地规则，`llm_calls` 里只有跳过记录。
  要评大模型质量得配好密钥再跑——那时成本、失败率、重试次数才会有值。
- **已知噪声（下一步优化的靶子）**：
  - 待办库 64 项里有 4 项来自图片附件（`[图片] …选课时间安排表`），被误判成待办；
  - 380 条噪声里有 2 条被推出去；
  - 26 条该推的因为同批超上限 / 被去重没能送达——这正是**召回 100% 但送达 69.8%** 的来源。

## CI 门槛

`tests/test_benchmark.py` 用 150 条 / `seed=5` 的小评测集做回归，断言不低于：

| 指标 | 下限 |
| --- | --- |
| 召回 | ≥ 90% |
| 误报率 | ≤ 10% |
| 待办判定 | ≥ 90% |
| 截止时间 | ≥ 90% |

门槛留了余量：规则或模型改动导致的**真实倒退**会被拦下，正常的小幅波动不会天天红。

## 不在评测范围

- **真实多模态质量**：图片 / 文件的识别准确率取决于模型，离线回放测不了；
- **跨天窗口**：评测集只铺一天 16 小时，跨天合并策略不在指标里；
- **线上通道可靠性**：投递重试、配额、通道失败另有 `doctor` 与 [故障演练手册](DR-DRILL.md) 覆盖。
